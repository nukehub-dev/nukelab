# Frontend

## Purpose

Vite + React 19 single-page application for the NukeLab platform admin dashboard and user interface.

## Ownership

All files under `frontend/` except generated artifacts (`node_modules/`, `dist/`, `.tanstack/`, `test-results/`).

## Local Contracts

- React 19, TypeScript ~6, Tailwind CSS v4, TanStack Router/Query/Table, Zustand, Playwright for e2e tests.
- `src/main.tsx` is the entry point; `src/routeTree.gen.ts` is generated by TanStack Router.
- `e2e/` owns Playwright end-to-end tests.
- Service worker cache injection is handled by `scripts/inject-sw-cache.cjs` during `npm run build`.
- Server creation returns `Server | QueuedServerAcceptance`; discriminate on `queued: true` before reading server identity. Accepted requests keep their saved name/configuration and navigate to `/servers?tab=queue&request=<id>`. Deployment dialogs initialize only when opened, preserve selections through failed requests/catalog refreshes, and prevent duplicate pending submits.
- `src/hooks/use-server-queue.ts` owns capability-gated owner queue queries and cancellation. Queue keys include owner identity and are cleared/cancelled on account changes and logout. Query `/server-queue/capabilities` before exposing queue controls; unsupported deployments must not query queue records. Queue lists support server-side Active/Started/History/All status filters; filters are part of the owner-scoped query key, only active/all views poll, and active requests refresh every five seconds with bounded failure backoff and pause in hidden tabs. Cancel only server-confirmed pending requests, refresh on conflicts, and show priority position without promising a start time.
- `src/hooks/use-jobs.ts` owns the owner Jobs surface at `/jobs` and `/jobs/$jobId`. Query `/jobs/capabilities` before job records; `enabled` controls history/detail/log queries and `can_submit` plus `JOBS_WRITE_OWN` gates creation. All keys include owner identity and are cancelled/cleared on account changes and logout, with late mutation feedback suppressed. Active lists and details poll with bounded failure backoff and pause in hidden tabs; logs fetch on open or explicit refresh rather than polling. Submission reuses one `Idempotency-Key` only for an unchanged request; a replay opens the existing job. The dialog uses searchable pickers for environment revisions, CPU plans, and owned private volumes; the volume picker links to `/volumes` and can refresh its list. All active CPU plans marked for batch jobs are shown, with paid plans disabled and explained while paid jobs are off; server-only plans stay out of the job picker. Maximum runtime accepts seconds, minutes, or hours and is converted to whole seconds before submission. Arguments are entered one literal argument per line (no shell parsing). Disabling submission disables the New job action but keeps history, detail, logs and cancellation; cancellation is available only while the server says the job can be cancelled. When capabilities report `billing_mode=paid`, paid plans are eligible and the dialog quotes the rounded-up maximum hold with a one-NUKE minimum; unused credits are refunded after the terminal result. Job detail renders the server's held, settled, released, or unpaid billing amounts. Zero-cost jobs keep the existing zero-cost copy.
- Job logs are fetched separately from the detail payload and rendered only from the server's bounded state (`pending`, `available`, `truncated`, `unavailable`, `expired`); never imply the retained tail is the complete output.
- `/servers?deploy=true` is the first-run/deploy deep link. It opens the existing deploy dialog once, then removes the flag so closing or refreshing does not reopen it; the dashboard first-run card and Deploy quick action use it. The dashboard and deploy dialog preselect eligible current catalog defaults without inventing IDs, surface stale saved plan/environment defaults instead of submitting them, and let the user review or change every preselected value.
- `/admin/setup` is the first-run catalog checklist for admins: publish an active public environment, make at least one active plan available to the `user` role, and review users/launch testing. It links to the existing environment/plan/user managers rather than duplicating their forms. The dashboard and deploy dialog must show a prerequisite state when no usable catalog exists; never present a deploy CTA that cannot become valid.

- `src/hooks/use-server-provenance.ts` owns capability-gated owner history and recreation queries. Provenance and plan/volume catalogs are actor-scoped, cleared on account changes, and protected against late responses. The detail panel labels records as the last verified launch and shows current server status rather than implying an uncertain replacement is verified.
- Environment export downloads sanitized server-returned JSON for the displayed launch. Source recreation and manifest import require server validation followed by a new name, current plan and explicit fresh/existing volume bindings; no source volume IDs are copied automatically. Validation is a preview, never an authorization grant. Final recreation uses the same Server-or-Queued response contract as deployment.

- `src/hooks/use-volume-backups.ts` owns actor-scoped recovery capability, eligibility, backup and restore history. Unsupported deployments hide recovery controls; supported but disabled storage/helper configuration keeps owner history readable while disabling mutations. Active records poll with hidden-tab and failure backoff, and account changes clear their cache and suppress late mutation feedback.
- Volume backup/history uses backend private/offline eligibility and action flags rather than server counts. Restores require a deliberate new name/capacity, retain retry request identities, never overwrite source data, and show destinations for use only after completion. Deleted-source backups remain reachable through global history; no archive upload/download or automatic workload stopping is exposed.
- `src/hooks/use-environment-revisions.ts` and the admin environments revision panel are gated by `ENVIRONMENT_READ`/`ENVIRONMENT_UPDATE` + `ADMIN_ACCESS`. The panel lists sanitized revision metadata, verifies current artifacts with a bounded reason, and revokes with history preserved. Last-selectable revocation requires an explicitly checked confirmation that is unchecked by default; there is no un-revoke control.
- `src/hooks/use-admin-operations.ts` and `/admin/operations` are gated by `OPERATIONS_READ_ALL`/`OPERATIONS_MANAGE_ALL` + `ADMIN_ACCESS`. The console renders only sanitized operation evidence, never request payloads, mounts, environment values, tokens, or raw runtime payloads. Reconcile requires a bounded reason and has no force/override control; ambiguous evidence must state that no mutation or reservation release occurred. Target/owner display names are sanitized and fall back to short IDs.
- `/admin/queue` is a read-only cross-owner view. Owner filtering uses a directory picker only when `USERS_READ` is present, otherwise the bounded UUID input remains. Queue display names/resources are sanitized; summary counts honor owner/age/recovery filters but deliberately ignore the status chip.
- Plan availability is explicit: `allow_servers` filters the server catalog and is enforced by server launch; `allow_batch_jobs` opts a CPU-only plan into the Jobs form, and job-only plans stay out of server deployment. Admin → Plans shows a Usage badge and exposes both checkboxes; the same hourly cost applies to both. Missing legacy flags are treated as enabled in the client for rolling-deploy compatibility.
- `src/hooks/use-admin-jobs.ts` and `/admin/jobs` are a cross-owner batch-job view gated by `ADMIN_ACCESS` plus any of `JOBS_READ_ALL`, `JOBS_ACCESS_OTHERS`, or the legacy `OPERATIONS_READ_ALL`. Cancel and reconcile additionally require `JOBS_WRITE_ALL` or the legacy `OPERATIONS_MANAGE_ALL`, and appear only on server-marked `can_cancel`/`can_reconcile` rows. Filters cover active/history/all plus a bounded age filter and limit/offset, and the query key includes the current actor id and those filters. Account switch/logout cancels and removes the previous actor's `admin-jobs` cache namespace so a late old-actor response cannot repopulate it. It shows sanitized state/reason, owner/environment/plan/volume labels, reservation and volume-guard flags, heartbeat age, and log/cleanup state with age-filtered summary counts. It never requests or renders argv, logs, environment values, or runtime identity, and has no retry or force/override control. Cancel requires a bounded 8-500 character reason and explains that queued jobs release their hold immediately while started jobs keep reservation/volume-guard/hold protection until proof-backed termination; `recovery_required` is reconcile-only. Reconcile requires the same reason bounds, renders only sanitized outcome/proof fields, refreshes instead of optimistically mutating the row, and states that ambiguous evidence releases no reservation or volume guard.
- The environment revisions panel supports loaded-page filters (All/Registry verified/Local only/Revoked) and search by revision ID/fingerprint/image/reference. Copy controls copy full IDs, fingerprints, and manifest digests without truncation.

## Work Guidance

### Project structure

- `src/routes/` — TanStack Router file-based routes. Each route file exports a default component and may export `Route` metadata. The route tree is regenerated automatically on `npm run dev` or via `npx tsr generate`.
- `src/components/` — reusable UI components. Prefer composition over large monolithic components.
- `src/hooks/` — custom React hooks, especially data-fetching wrappers around TanStack Query.
  - `src/hooks/use-activity-heartbeat.ts` — pings `POST /servers/:id/activity` every 30s only while the tab is visible AND the user interacted within the input window (`src/lib/activity-heartbeat.ts`); an open-but-untouched tab must not block idle shutdown.
  - `src/hooks/use-page-guard.ts` — page-level RBAC guard hook that redirects unauthorized users.
  - `src/hooks/use-is-desktop.ts` — viewport ≥lg (1024px) check; gates expensive visual effects off mobile and mounts responsive-only content exactly once (e.g. `Dialog` children render in either the mobile sheet or the desktop drawer, never both).
  - `src/hooks/use-keyboard-shortcuts.ts` — global shortcuts; `'mod'` modifier = ctrl-or-meta, optional `permission` gating. Global search palette (`src/components/search/command-palette.tsx`, backed by `src/hooks/use-search.ts`) opens via the `show-search` window event, bound to `Ctrl+K` (mod) and `/`. Scoped filters: a leading `/users` or `users:` token narrows the search to one entity group (sent as the `group` API param with `limit=10`). Static Go-to commands rank above entity results and cover all user and admin pages — each admin command gated by its route guard's permission — with `keywords` aliases, plus an admin-only Grafana action that opens via the monitoring auth redirect.
- `src/stores/` — Zustand stores for client-side state that does not belong in the URL or server cache.
  - `src/stores/auth-store.ts` — auth store with user state, `PERMISSIONS` constants, and permission helpers.
  - `src/stores/timezone-store.ts` — non-persisted mirror of the backend `timezone` preference (`'auto'` or an IANA zone → `effectiveZone`), synced by `src/hooks/use-timezone-sync.ts`. Keep it self-contained; `lib/utils.ts` imports the store, never the reverse.
- `src/lib/` — pure utility functions and shared constants.
  - `src/lib/external-links.ts` — single source of truth for external destinations (NukeTalk community, contact page, blog). Import `EXTERNAL_LINKS`; never hard-code these URLs.
  - `src/lib/utils.ts` — backend timestamps are naive UTC (ISO 8601 without Z/offset). Parse and format every API timestamp through `parseUtcDate` / `formatDate` / `formatRelativeTime` from this module; never call `new Date(apiString)` directly. Formatters apply the user's timezone preference (default auto/browser, stored in the backend `timezone` preference) and use the browser locale; date-only `YYYY-MM-DD` strings go through `parseLocalDate` / `formatDateOnly`.
- `src/api/` — generated or hand-written API client code and request/response types.

### Adding a route

1. Create a route file under `src/routes/` matching TanStack Router conventions (e.g., `servers.$serverId.tsx` for `/servers/:serverId`).
2. Export `Route` from `@tanstack/react-router` with path, component, and loader/error boundaries as needed.
3. Run `npx tsr generate` or restart `npm run dev` to regenerate `src/routeTree.gen.ts`.
4. Add an e2e test in `e2e/` if the route is user-facing.

### Fetching data

- Use TanStack Query hooks for server state. Define queries in feature-specific hooks under `src/hooks/` rather than inlining them in components.
- Keep query keys stable and predictable; include IDs and filter parameters.
- Handle loading and error states explicitly; use skeletons or error boundaries instead of silent failures.

### Role-based access control (RBAC)

The frontend mirrors the backend permission model for UX purposes only. The backend remains the ultimate authority on every request.

- **Permission constants**: `src/stores/auth-store.ts` exports `PERMISSIONS`. These strings must match `app/core/permissions.py` in the backend exactly.
- **Checking permissions**: use `useAuthStore` selectors or the helpers it exposes:
  - `hasPermission(permission)` — single permission.
  - `hasAnyPermission([perm1, perm2])` — any of the listed permissions.
  - `hasAllPermissions([perm1, perm2])` — all listed permissions.
- **Page guards**: `usePageGuard` redirects unauthorized users. It waits for the first `/users/me/profile` load when a token exists, so deep links/refreshes do not bounce an authenticated admin to the dashboard while the persisted auth store is still empty. Use it at the top of route components:

```tsx
import { usePageGuard } from '../hooks/use-page-guard'
import { PERMISSIONS, useAuthStore } from '../stores/auth-store'

function AdminCreditsPage() {
  const allowed = usePageGuard({ permission: PERMISSIONS.CREDITS_READ_ALL })
  const canGrant = useAuthStore((state) => state.hasPermission(PERMISSIONS.CREDITS_GRANT))

  if (!allowed) return null

  return <div>{canGrant && <GrantCreditsButton />}</div>
}
```

- **Route links**: in `admin.index.tsx` and other navigation lists, use `requiredPermission` to hide links the user cannot access.

#### Adding or changing permissions

1. Add the constant to `PERMISSIONS` in `src/stores/auth-store.ts`.
2. Update the role fallback mapping in `checkPermission` if the permission should be derivable from a role when the backend has not sent an explicit permissions list.
3. Update the admin permissions matrix UI (`src/routes/admin.permissions.tsx`) if the permission belongs to a new or existing category.
4. Hide guarded UI behind `useAuthStore` permission checks; always expect the backend to enforce the same restriction.

#### Important rules

- Client-side permission checks are for UX only. Never trust the frontend to enforce authorization — the backend must validate every request.
- Keep `PERMISSIONS` in sync with the backend `Permission` class. A mismatch will cause false denials or hidden features.
- Do not hard-code role names like `role === 'admin'` for access decisions unless the semantic truly depends on role identity. Prefer permission checks so dynamic role overrides continue to work.

### State management

- Prefer URL state for page-level filters and selections.
- Use Zustand for global UI state that should survive navigation (e.g., sidebar collapse, theme).
- Avoid prop drilling more than two levels deep; use context or Zustand instead.

### WebSocket

- One shared connection per app, owned by `src/contexts/websocket-provider.tsx` (`useWebSocket`); consumers use `useSharedWebSocket` and room scopes (`global`, `server:<id>`, `user:<id>`).
- Global notification toasts live in `src/components/notifications/notification-toast-provider.tsx`. Deduplicate by notification id across WebSocket and polling delivery, retain a bounded id set in `sessionStorage`, and suppress the old-unread backlog on mount without suppressing live events or replays from shell remounts.
- The connection lifecycle is self-healing: it reconnects on `visibilitychange`/`online`, forces a reconnect when a socket looks open but has been silent past the zombie threshold, and refreshes an expired token on auth failure (4001) instead of dying permanently. Do not add per-feature reconnect logic — fix the shared hook.
- Live dashboard metrics (`useDashboardMetrics`) depend on the `global` room; system metrics publish every 60s, container metrics every 5s.

### Styling

- Use Tailwind CSS utility classes. Avoid arbitrary values; extend the theme in `tailwind.config.ts` when a value repeats.
- Prefer `className` composition with `clsx` or `tailwind-merge` for conditional classes.

### UI components

- The project does **not** use a generic component library. Build custom components in `src/components/ui/` as needed.
- Reuse existing `src/components/ui/*` components before writing new ones (e.g., `Tooltip`, `Button`, `Modal`, `Toast`). Use `Combobox` for long searchable option lists and `Select` for short fixed choices. Option labels must wrap or truncate inside the trigger width; long plan, environment, or volume names must never create horizontal scrolling.
- Do **not** rely on browser-built-in UI for product UX. For example, use the project's own `Tooltip` component (`src/components/ui/tooltip.tsx`) instead of the native `title` attribute.
- Keep components in `src/components/ui/` small, accessible, and styled consistently with Tailwind. Export a clear prop interface and avoid leaking layout concerns into reusable primitives.

### Forms and validation

- Use controlled inputs with React state or a form library consistent with the project.
- Validate user input before submission; display field-level errors returned by the backend.
- Token scope options in `src/components/settings/tokens-page.tsx` (`AVAILABLE_SCOPES`) must match `VALID_TOKEN_SCOPES` in `backend/app/api/tokens.py`; the backend rejects unknown scopes with 422.

### Tests

- `npm run test` runs Playwright e2e tests. Write e2e specs for critical user flows.
- `npm run test:unit` runs Vitest unit tests (colocated `*.test.ts` under `src/`). Add unit tests for pure helpers in `src/lib/` and `src/hooks/`.
- Playwright has two modes. Local development is the default: Vite starts on `http://localhost:5173`. Set `E2E_EXTERNAL_SERVER=1` to target a prestarted single-origin stack through `BASE_URL` (normally `http://localhost:8080`); this mode must omit the Vite `webServer`. Never point `BASE_URL` at a prestarted stack while leaving external mode off.
- `frontend/e2e/fixtures/runtime.Dockerfile` builds disposable runtime A/B images from `nukelab-environment-base`. Keep the fixture image aligned with the real base runtime (`/start.sh`, nginx port 8080, auth sidecar, non-root contract); it is not a generic `nginx:alpine` substitute.
- Real-stack specs use unique per-run users, environments, volumes and servers, and clean up only resources they created. The shared helpers in `frontend/e2e/helpers/` own login, API calls, readiness polling and unique names.
- Playwright tags select coverage in CI: `@workspace` runs against the built IDE image, `@combined` runs the provenance + offline recovery + queued recreation scenario when `E2E_COMBINED=1`, and `@vite-only` identifies account-switch tests that import running Vite source modules and therefore run against Vite with mocked HTTP. Do not replace these with production-bundle stubs.
- CI runs `test:unit`, the Vite-only mocked browser set, the disposable external stack, and the workspace/IDE stack as required gates. Failure artifacts are limited to Playwright reports, traces and targeted container logs; never upload env files or raw tokens.

### Build and service worker

- `npm run build` produces `dist/`. The service worker is generated and cache injection runs automatically.
- Edit `public/sw.js.tpl` for service worker behavior; `public/sw.js` is generated by `scripts/inject-sw-cache.cjs` during build. Do not manually edit generated files in `dist/` or `.tanstack/`.
- Push notification helpers live in `src/lib/register-sw.ts`. Enable dev registration with `VITE_ENABLE_PUSH_IN_DEV=true`.
- Route-level code splitting is enabled via the TanStack Router Vite plugin (`autoCodeSplitting: true`). Do **not** set `enableRouteGeneration: false`: the code splitter only processes files the generator registers, so disabling generation silently produces a single monolithic bundle.
- `src/routeTree.gen.ts` is regenerated on every dev/build and is excluded from Prettier; the generator's formatting is authoritative for that file.

### Common pitfalls

- `nukelabctl test frontend` does **not** accept path passthrough. Scope Vitest with `cd frontend && npm run test:unit -- path/to/file.test.ts`; scope Playwright with `npm run test -- path/to/file.spec.ts`.
- `useConfirmDialog`'s `customContent` is stored as a one-time element snapshot: parent-state-driven props inside it never update. Interactive fields must be self-contained components that own their state and report values through a stable ref (see `BlockRequestFields` in `src/components/admin/credits/users-tab.tsx`).
- Do not import route files directly; rely on the generated route tree.
- Keep environment-specific values in `.env.*` files, not hard-coded in source.
